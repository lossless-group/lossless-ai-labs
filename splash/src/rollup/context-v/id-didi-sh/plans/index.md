# Plans

* [Bring the spike under the credential design system](Bring-The-Spike-Under-The-Credential-Design-System.md) - The splash already has a real three-mode design system — verdigris, copper, and security-teal on vault-black. The Phoenix app has never seen it: it is stock generator output, down to the framework logo and the orange light theme. Five increments to close the gap, starting with the two DESIGN.md files that currently describe a different product entirely.
* [Entities and keys — implementation plan for id-didi-sh](Entities-and-Keys-Implementation-Plan.md) - Build the flat entity model and credential lending into the Phoenix service: six tables, two contexts, a resolve path for server-side consumers, and eight increments each ending in something you can observe rather than believe.
* [OAuth Authorization Server for Claude Connectors](OAuth-Authorization-Server-for-Claude-Connectors.md) - Discovery, authorize, token, refresh, and client registration on id.didi.sh, so Claude can sign a partner into MemoPop with one magic link.
* [Storage and backups for id-didi-sh](Storage-and-Backups-for-id-didi-sh.md) - Move to Turso, because being able to log in and fix a row by hand beats driver purity when there is one operator. Backups stop being a project and become a checkbox.
