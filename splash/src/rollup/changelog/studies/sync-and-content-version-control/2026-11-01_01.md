# The Sync and Version Control Study's Profiles Become an OKF Bundle

## Why Care?

This study asks where history should live when a folder is shared between an operator and a non-technical client over blob storage. Its answer is spread across eight profiles of pinned upstream tools: Automerge, git-annex, Jujutsu, Kopia, Rclone UI, restic, Seafile, and Syncthing. Until today an agent had to open each one to learn what it was. Now `context-v/` is an Open Knowledge Format (OKF) v0.2 bundle, so any OKF reader can list the profiles and what each one found without opening a file.

## What's New?

- **All 8 profiles declare `type: Profiles`**, the Train-Case name of the folder they live in.
- **`context-v/index.md`** marks the bundle with `okf_version: "0.2"` and lists its one folder.
- **`context-v/profiles/index.md`** has one line per profile, with its lede.
- **This `changelog/`** is new; this is its first entry.

## Under the Hood

- Part of the tree-wide OKF sweep; see the Context Vigilance Kit's plan, [[Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter]].
- Every edit was made by hand, one file at a time. The doc diff is 8 added `type:` lines and nothing removed. No dates moved: this is a compliance change, not a content change.
- The pinned upstream repos beside `context-v/` were not touched.
- `development` and `master` were created at `main`'s commit first, so the repo has all three tiers.
