## Why Care?

The splash pointed at the specs and changelog on GitHub but didn't show them.
The older way to show children's content was a sync script that copied their
files into the splash, which left the same entry in two places and drifting.

## What's New?

- **`/changelog/`**: every entry, newest first, with the repo it came from.
- **`/context-v/`**: the written-down work grouped by folder (specs,
  blueprints, plans, reminders, sitemap), with jump links.
- **Entry pages** for both, linking back to the file on GitHub.
- **Read, not copied.** This repo's files come from the checkout. Children
  listed in `.gitmodules` come from the GitHub API at build time: one tree
  request per child, then each file by its hash.
- **Public only.** A child is read only if its repo is public and it isn't
  under `client-sites/`. Anything that can't be confirmed public is skipped,
  so a private repo can't leak onto this public page. Today that admits
  `dididecks-player` and skips the private `corpus`. Files marked
  `publish: false` or `private: true` stay out.
- **Deploys when content changes.** The Pages workflow now also runs on
  changes to `changelog/`, `context-v/` and `.gitmodules`.
