## Why Care?

Design Principle #6 is "passable PDF export, indistinguishable from Keynote/PPT." In practice the export surface was scattered and uneven:

- `reach-edu-hub` had a genuinely good **native-shape** PPTX exporter — but it lived in that repo, and it only works for decks whose copy exists as content modules.
- `calmstorm-decks` had a Playwright PNG→PDF exporter, a different script, no PPTX at all.
- Nobody had `.key`, and nobody had per-element export.

A client-site that wants to hand a funder a `.pptx`, or hand a designer the logo set, shouldn't have to grow its own exporter. `@dididecks/deck-export` is one CLI with six commands that works against **any** deck site.

## The design decision everything follows from

**The exporter drives a running site over HTTP and never imports its source.** It works against `astro dev`, `astro preview`, or a deployed URL, and needs zero knowledge of how a client-site organises slides. A site hands over a list of capture URLs — either `--pattern '/dev/shot/{slot}/{variant}'` or an explicit `--routes routes.json` — and everything downstream operates on that one flat shape.

That's what makes it work for calmstorm, which is **not** a shell consumer and not even a workspace member, without special-casing it.

## What's New?

| Command | Produces |
|---|---|
| `slides` | @2x PNG, transparent PNG, outlined-vector SVG |
| `pdf` | one PDF per variant, **live selectable text** |
| `pptx` | one PPTX per variant, image-backed |
| `keynote` | real `.key` via Keynote automation |
| `elements` | asset library + `manifest.json` + contact sheet |
| `all` | slides → pdf → pptx → elements |

Proven on calmstorm: **51 slides, 3 vector PDFs, 3 PPTX, 3 `.key`, 101 deduped assets.**

Incidentally, the vector PDFs are **5.2 MB vs the previous 20 MB** raster-stitched ones, and their text is searchable.

## Three things measured rather than assumed

**SVG text is outlined; PDF text is live.** `pdftocairo -svg` emits each glyph as `<symbol>`+`<use>` paths, not `<text>` — the SVG scales and recolors in Figma but a headline can't be re-typed. The PDF keeps live text (`pdftotext` extracts it cleanly). An earlier draft of this package's docs claimed SVG preserved editable text; it does not, and the module now says so. Reach for the PDF when text matters, the SVG when geometry does.

**The PPTX is image-backed, and says so out loud.** One full-bleed picture per slide: exact fidelity, zero editability. Slide 1's speaker notes state this explicitly so nobody discovers it mid-meeting. A **native-shape** PPTX needs the deck's copy as structured data per `context-v/blueprints/Shared-Content-Modules-Across-Deck-Surfaces.md`. reach has those modules; calmstorm's copy lives in hand-authored Astro markup, so a native export there means transcribing 17 slots × 3 variants first. That's a project, not a flag — recording it here so it isn't rediscovered as a surprise.

**`.key` works, and the trap is one word.** `save <doc> in <file>` writes Keynote's native format. Adding `as Keynote` fails with `AppleEvent handler failed (-10000)` and writes nothing — Keynote's `as` parameter takes an *export* format enum. The error names neither the parameter nor the file. Both the module comment and the README carry a warning.

## The bug the smoke test caught

The elements manifest claimed **197 assets while only 103 files existed on disk**. Cause: `firms` walks both `src/assets/firms` and `data/firms`, and calmstorm keeps the former as a byte-identical 96-file subset of the latter. Same relative sub-paths → the copies silently overwrote each other while the manifest counted both.

Fixed by making **identity content, not path**: assets dedupe on SHA-1, one canonical copy is exported, and every other path carrying those bytes is listed in that entry's `alsoAt`. Manifest and disk now reconcile exactly (101 = 101, 96 with `alsoAt`). A separate guard renames rather than overwrites if two *different* files ever contend for one destination.

Worth generalising: any exporter that walks multiple source trees needs this. Nested categories (`public/backdrops` inside `public`) need first-claim-wins; duplicated content at different paths needs content hashing. They are different problems and only one is fixed by ordering.

## Not done

- **Native-shape PPTX for calmstorm** — blocked on content-module transcription (above).
- **Live text in SVG** — would need `mutool` or Inkscape in the pipeline; neither is currently a dependency.
- **Publishing the package** — it runs from source in-workspace. A `--filter` install currently fails on an unrelated missing `GITHUB_TOKEN` for the private registry, so deps were installed with `--ignore-workspace`.
