# DidiDecks' Docs Say What Shipped, and When

## Why Care?

[[2026-11-01_01]] made `dididecks-ai/context-v/` an Open Knowledge Format bundle. This pass brings the same docs up to the Context Vigilance Kit's frontmatter template, so a workflow dashboard can tell what's shipped, what's partway, what's parked, and what's reference material, and can sort shipped work by when it actually landed.

## What's New?

- **Every status is on the kit's list.** 24 sitemap pages said `shipped` and now say `Shipped`. `Mostly-Shipped`, `Phases-A-D-Shipped`, and `partial` became `Partially-Shipped`. The data models, which said `As-observed-from-filesystem`, are `Reference`. A `Parked` exploration is `Deferred`, with its own reason as the `deferral_note`. A deprecated sitemap component is `Superseded` and points at its replacement.
- **Ship dates from commits.** 28 docs gained a `date_first_published`: for each sitemap page, the commit that first added the code it describes; for each plan, the commit of its first shipped slice.
- **Identity for 10 more docs.** Ten plans and prompts had no `site_uuid` or `hex_code`; each now has its own.
- **Authors on the data models**, from their only human committer.
- **28 AI credits became lists**, the string kept word for word.
- **Repo names came out of tags** on 14 docs whose bodies already name the repo (`Chroma-Decks`, `Calmstorm-Decks`, `Dididecks-AI`, and others). The product name `Dididecks` and the `Dididecks-Shell` package stay where they're the subject.

## Under the Hood

- Part of the tree-wide OKF sweep; see the Context Vigilance Kit's plan, [[Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter]], and the status vocabulary in the context-vigilance skill's `status-discipline.md`.
- Every edit was made by hand, frontmatter only. No body line changed, no existing date moved, and today's date was written into no existing doc.
- Status calls were made by reading each doc and checking the code: a route counts as `Partially-Shipped` only where part of it exists in `apps/deck-shell`.
- The `Partially-Shipped` docs don't yet have a `## Remaining work` section; their existing status notes carry that for now.
