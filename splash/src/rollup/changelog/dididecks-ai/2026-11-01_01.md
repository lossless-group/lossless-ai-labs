# DidiDecks' 81 Docs Become a Bundle Any Agent Can Read

## Why Care?

`dididecks-ai/context-v/` is the working memory of the deck operating system: the plans that sequence each client remake, the data models behind decks, variants and slots, and a sitemap of every route and component. Until today an agent landing here had to open each of its 81 files to learn what kind of doc it was. Now the folder is an Open Knowledge Format (OKF) v0.2 bundle, so any OKF reader can list what's here and what each doc is for without opening a thing.

## What's New?

- **All 81 docs declare their `type`**, the Train-Case name of the folder they live in: `Sitemap` (29), `Plans` (18), `Models` (9), `Explorations` (8), `Specs` (6), `Prompts` (6), `Blueprints` (2), `Reminders` (2), `Loops` (1).
- **`context-v/index.md`** marks the bundle with `okf_version: "0.2"` and lists its nine folders.
- **Nine folder indexes**, one line per doc with its lede. The sitemap index has a heading per subfolder (components, lib, routes, runtime), and a superseded exploration is marked as such.

## Under the Hood

- Part of the tree-wide OKF sweep; see the Context Vigilance Kit's plan, [[Retrofit-Every-Repo-to-OKF-Then-the-Kit-Frontmatter]].
- Every edit was made by hand, one file at a time. The whole doc diff is 81 added `type:` lines and nothing removed. No dates moved: this is a compliance change, not a content change.
- The folder READMEs in `models/`, `prompts/`, and `sitemap/` carry frontmatter, so they are typed and indexed like any other doc.
- `models/` is not one of the canonical context-v folders; it keeps its name, and its type follows it.
- The client sites under `client-sites/` are their own repos and their own bundles.
