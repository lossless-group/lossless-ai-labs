## Why Care?

The last two security alerts on dididecks-ai (an open redirect through
enhanced forms, and XSS through a cache-control header on prerendered pages)
are fixed only in SvelteKit 3. Moving now also keeps the product frontend on
the supported line before more is built on it.

***

## What's New?

- **SvelteKit 2 → 3.4**, with Vite 6 → 8, TypeScript 5 → 6,
  vite-plugin-svelte 5 → 7, adapter-vercel 6 → 7 and Svelte 5.57 or later.
- **Config lives in `vite.config.ts`.** `svelte.config.js` is gone, and so
  is the `kit.alias` block: `@dididecks/shared` now resolves through its
  own package exports.
- **`$lib` imports became `#lib`** (Node subpath imports) across the app.
  This was done by `sv migrate sveltekit-3` and accounts for most of the
  diff.
- **Four components moved to runes:** the root layout, the app sidebar and
  the two deck navs. They read the current page from `$app/state`.
- **Environment variables** are declared in `src/env.ts`.
  `PUBLIC_SITE_URL` and `PUBLIC_ORIGIN` stay optional.
- **API routes use `Response.json()`** in place of the deprecated helper.

The build is clean. The dev server serves the public, app, deck and API
routes, and the nav highlights the current page. `svelte-check` reports
the same 3 errors it did before the migration.
