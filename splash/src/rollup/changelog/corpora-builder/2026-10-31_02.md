## Why Care?

The context-vigilance kit has a baseline every doc's frontmatter should carry:
`title`, `date_created`, `date_modified`, `site_uuid`, `hex_code`, and
`authors`. Tools that sort, date, and attribute docs read those fields, so a
doc missing one quietly drops out of a view. This is the second half of the
retrofit sweep: fill the gaps from facts, and bring existing values into the
standard shape.

## What's New?

24 of the 26 docs already carried the full baseline. The two that didn't were
the oldest drafts, written before the template settled:

- **`blueprints/Source-File-Schema-Reconciliation.md`** gains
  `date_created: 2026-08-08` (its `date_authored_initial_draft`) and
  `date_modified: 2026-08-18` (its last commit before this sweep).
- **`plans/Corpora-Builder-MVP-R2-Native-With-Checkpoint-History.md`** gains
  `date_created: 2026-08-08` (its `date_authored_initial_draft`) and
  `date_modified: 2026-08-22` (its last commit before this sweep).
- In both, `augmented_with` moves from a bare string to a one-item list, with
  the model string unchanged.

## Under the Hood

Facts only. Every added date comes from the doc itself or from `git log`, none
is the day of the sweep, and no existing value, status, version, or body line
changed. Each edit was made by hand; no script wrote frontmatter.

Left as written: `semantic_version:` in the docs that use it (a permanent
alias of `at_semantic_version`), `date_last_updated`, and the spec template's
placeholder dates.
