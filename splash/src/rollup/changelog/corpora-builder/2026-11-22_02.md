## Why Care?

Opening a codebase to answer "what does this folder do, and what can I call
in it?" costs a person ten minutes and an agent a pile of file reads. A
mirror answers it from one page per folder. It doesn't plan or argue the way
a spec or blueprint does. It reports what the code is today, and it's meant
to be re-taken from the source when the code moves, never edited from memory.

## What's New?

- **`context-v/mirrors/` copies the repo's tree.** One `index.md` per mirrored
  folder, at the same path: `mirrors/src/server/index.md` describes
  `src/server/`. It goes down to each Python package and each frontend
  folder, not into every subfolder.
- **Every code file is covered: all 102.** Each gets its purpose, what it can
  do where that isn't obvious, and its interface: functions and classes with
  real signatures, constants, server routes, Svelte props, CLI commands.
- **The root page carries the whole map**: the tree, how the pieces connect,
  the outside services, and every environment variable the code reads.
- **Each page says how to re-take it**, and names the commit it was taken at.

## How it was taken

The signatures weren't typed by hand. Python interfaces were read from the
source with `ast`. TypeScript, Svelte and Rust surfaces came from their
`export` lines, `Props` interfaces and `fn` definitions. One-line purposes came
from the floorplan we drew of the repo earlier the same day. The prose (what
each folder is for, what it can and can't do) was written after reading the
code, and claims that weren't obvious were checked against it before
committing.

Checking turned up two facts worth having on the page:

- **Duplicate detection is per folder.** `add_source` looks for the same
  `normalized_url` only in the destination folder, so the same link filed
  under two domains is not caught.
- **The packaged app starts read-only.** The launcher sets only `CORPORA_PORT`
  when it starts the server, so capture from the screen answers 403 unless
  `CORPORA_WRITABLE=1` is already in the environment the app started from.

## What's Next?

The context-vigilance skill still describes a mirror as one document about
live infrastructure (its first example is a Railway project). This one is a
tree that mirrors a codebase. Whether both shapes belong under `mirrors/` is
the open question this entry leaves.
