## Why Care?

Dependencies left alone don't stay still: they drift until one upgrade turns
into five breaking ones at once, usually on the day you need something new.
corpora-builder runs on three stacks (Python for the engine, SvelteKit for the
screen, Rust for the desktop launcher), so we moved all of them to their
latest releases in one deliberate pass, one step per commit, testing each
before taking the next.

## What's New?

| Stack | Before | After |
|---|---|---|
| Python | fastapi 0.141, uvicorn 0.52, boto3 1.43 | fastapi 0.165, uvicorn 0.54, boto3 1.44, ~45 others |
| Screen | SvelteKit 2.70, Vite 7, TypeScript 5.9, Svelte 5.56 | **SvelteKit 3.4, Vite 8, TypeScript 6.0**, Svelte 5.59 |
| Launcher | tauri 2.11, reqwest 0.12 | tauri 2.12, reqwest 0.13, 255 crate updates |

Six commits, safe updates before majors, so any single step can be reverted
on its own:

1. Python lockfile refresh
2. App packages within their current majors
3. Vite 7 → 8
4. TypeScript 5.9 → 6.0
5. SvelteKit 2 → 3 with adapter-static 3 → 4
6. Rust crates, with reqwest 0.12 → 0.13

## Held back, and why

- **TypeScript 7.** Released, but `svelte-check` accepts TypeScript 5 or 6
  only, and SvelteKit 3 declares `^6`. It waits for the Svelte toolchain.
- **Tauri 3.** Still an alpha. The launcher stays on the newest Tauri 2.
- **python-dateutil 4.** `botocore` requires `<3.0`, so it stays on 2.9.

## How SvelteKit 3 landed

The one upgrade that touched code. It failed three times, each with a clear
error, each fixed before moving on:

1. **`svelte.config.js` is gone.** Its presence is now a build error. The
   static adapter and preprocessor moved into `sveltekit({...})` in
   `vite.config.js`.
2. **`tsconfig.json` extends `$app/tsconfig`.** Kit now writes its generated
   config into `node_modules` rather than `.svelte-kit/`.
3. **`$lib` was removed in favour of `#lib`.** We tried the migration: Vite
   resolved `#lib/…`, but `svelte-check` couldn't find extensionless `#lib/`
   imports. More to the point, this app deliberately mirrors memopop-native's
   conventions, which spell imports `$lib/`, so copying code between them only
   works while both match. `$lib` is kept as an explicit alias, with a comment
   saying to migrate both apps together or neither.

## How it was tested

Every step ran the full check ladder: black, ruff, design drift, mypy, 210
pytest tests, 35 frontend tests, and the spec ledger (196 green, 0 red, 5
gated throughout). Frontend steps also ran `svelte-check` (0 errors, the same
two pre-existing warnings) and a production build.

Tests don't prove a framework major works in a browser, so after SvelteKit 3
we drove the real screen against a throwaway local corpus: page load,
listing, Rebuild index (the Pagefind 1.6 bundle builds and loads), ranked
search, the source reader and the file tree, with no console errors. After
the Rust step we ran the built launcher and watched it start the server and
pass its health check.

The codebase mirror's `app/` page was re-taken to match: no more
`svelte.config.js`, and `vite.config.js` now carries the configuration.
