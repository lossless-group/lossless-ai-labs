## Why Care?

The context-vigilance kit has a baseline every doc's frontmatter should carry,
and a standard spelling for each key. Tools that sort, date, and version docs
read those names, so a doc using an older spelling quietly drops out of a
view. This is the second half of the retrofit sweep: fill gaps from facts, and
bring existing keys into the standard shape.

## What's New?

All nine docs already carried `title`, `date_created`, `date_modified`,
`site_uuid`, `hex_code`, and `authors`, so nothing was added.

- **`specs/Master-Flave-An-Agent-Native-Document-Format-and-Publisher.md`**:
  `version: 0.1.0.0` becomes `at_semantic_version: 0.1.0.0`. Same value, the
  standard key. Nothing in this repo's code reads `version:` from frontmatter.

## Under the Hood

Facts only: no value, status, date, or body line changed, and the edit was
made by hand.

Left as written:

- The master spec's legacy `date: 2026-08-15`. Its two rename targets,
  `date_created` and `date_authored_initial_draft`, are both already present,
  so renaming it would duplicate a key.
- The document-service spec's `version:`, since it already has
  `at_semantic_version` with the same value.
- `semantic_version:` in the docs that use it, a permanent alias.
